# Add a feature, an RPC or a field

Read `AGENT.md` first. The reference feature is `projects`: copy the shape of its files. The example is a feature `pipelines` (`<feature>`, `<entity>` = `pipeline`, `<Entity>` = `Pipeline`).

## New feature

1. **Proto.** `proto/scylla/<feature>/v1/<entity>.proto` and `<entity>_service.proto`. Ids are `scylla.common.v1.Id`, lists use `PageRequest` and `PageResponse`. A comment on each item. Add the files to `scylla-proto/build.rs` and a module to `scylla-proto/src/lib.rs`. Run `buf lint`.
2. **Domain.** `scylla-domain/src/<subject>/<feature>.rs`, in the folder of its subject (`identity`, `tenancy`, or a new folder; `projects.rs` is the feature with the name of its subject, and `projects/secrets.rs` another feature of that subject): `KIND` (`ResourceKind::new(<Entity>::NAME)`), `pub type <Entity>Id = Id<<Entity>>;`, value types with `parse`, the entity, `New<Entity>`, `List<Feature>`, the page type. New error variants go in `DomainError`, with the reason only.
3. **Migration.** `sqlx migrate add --sequential --simple --source scylla-core/migrations <feature>`. Columns `id uuid PRIMARY KEY`, `workspace_id uuid NOT NULL REFERENCES workspaces (id)` and `created_by uuid NOT NULL REFERENCES actors (id)` with an index each, `created_at timestamptz NOT NULL DEFAULT now()`. No `owner_id`: only a workspace has owners, in `workspace_owners`. Run `just migrate`.
4. **Store.** `store.rs`: `insert`, `workspace`, `find`, `list_visible` (the caller for its owned workspaces, workspaces in a list, shared ids in a list, an optional workspace filter), `delete`, on `&mut Tx<'_>`, with `to_db()` and `from_db()` for ids. Map the workspace foreign key to `Error::NotFound("workspace")`.
5. **Service.** `service.rs`: begin, `hooks.before_create` or `hooks.after_delete` with the context (kind, actor, workspace), store, commit. No SpiceDB write: the workspace is in the row. A fact that an operator must see logs its business event after the commit (`AGENT.md`, Logs). After a delete, call `gate.delete_object(&Object::of(id))` to remove the roles. `find_workspace` gives the workspace of an object to `AccessService`.
6. **gRPC.** `grpc.rs`: `let caller = self.gate.caller(&request).await?;`, parse with `parse::required` (the workspace of a creation is required), `parse::field`, `parse::optional`, then `self.gate.authorize(&caller, <route permission>.on(id))`: `<Entity>Holder::CREATE_<ENTITY>.on(workspace_id)` for a create. On one object, read it or its workspace from Postgres first (no row gives `AccessError::denied(&caller, &check)`), then `<Entity>::GET_<ENTITY>.on(id).within(workspace)`. A list checks `<Entity>Caller::LIST_<ENTITIES>.on(caller.actor.id)`, then gets the workspaces with a role and the shared ids with `self.gate.granted(&caller, ...)` (a failed lookup gives no id). Answer with `ToProto`.
7. **Permissions.** In the domain file, one `crate::authz!` block: `extend Workspace as <Entity>Holder` with one permission for each route in the workspace (`permission create_<entity> = work;`, `permission delete_<entity> = manage;`), and `extend Actor as <Entity>Caller` for the routes on the caller (`permission list_<entities> = nil;`). A route on the whole instance goes in `extend Platform as <Entity>Holder` (`permission <route> = nil;`), and its check is `<Entity>Holder::<ROUTE>.on(Platform::ID)`: only the instance admins pass. If one object can be shared, also `definition <entity> for <Entity>` with roles (`relation viewer: Actor;`), groups (`permission view = edit + viewer;`), the route permissions on the object, and `permission grant = admin; permission revoke = admin;`. The name of a route permission is the RPC name in snake case.
8. **Plugin.** `plugin.rs`: `.authz::<<Entity>Holder>()` and `.authz::<<Entity>Caller>()` (and `.authz::<Entity>()` if the object has a definition). For a shared object, `.grants(AccessRoutes { grant: <Entity>::GRANT, revoke: <Entity>::REVOKE, list_access: <Entity>::LIST_ACCESS }, service::find_workspace)` (and `permission list_access = view;` in its definition) and one `.role(<Entity>::<ROLE>)` for each role. Then the service with `ctx.pool()`, `ctx.hooks()`, `ctx.gate()`. Install it in `scylla-core/src/app.rs`, after `Workspaces`. A core service that needs a part of `ServeOptions` (the mailer, the key of the secrets) is added in `api/serve.rs` instead, as `InvitationService` and `SecretService`, and its permissions go in the model of the plugin of its object.
9. **Tests.** One helper per RPC in the testkit file of its subject, `scylla-testkit/src/<subject>.rs` (with `app.authed`). A module `scylla-ce/tests/api/<subject>/<feature>.rs`: success, each error code, the boundaries of each value, the workspace of a creation, and a refusal for an actor with no role. Test the owner of the workspace (`app.workspace_of(user)`), a member and each role with `app.grant_role` (through `AccessService`) and `app.can`, and the list of a caller with a share. A unit test only for what the API cannot show.
10. **Finish.** `just prepare`, then the `finish-change` skill.

## New RPC on a feature

Proto (request and response messages), the route permission (the RPC name in snake case, in the `authz!` block of the feature, on a group), store function, service function (one transaction), handler method, testkit helper, API tests. If an edition must act on it, first add the hook with `change-extension-point`.

## New field on an entity

The column in the `CREATE TABLE` of the feature migration, then `just db-reset`, domain field (and value type if the server checks it), proto field with the next free number, store SQL, `ToProto`, request parsing, API test. A required field in `New<Entity>` breaks the Enterprise build at the next tag: tell the user.
